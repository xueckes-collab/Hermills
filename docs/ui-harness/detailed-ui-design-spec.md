# Hermills Detailed UI Design Specification

## 0. 设计总纲

Hermills 的 UI 不是“给 AI 工具套一层页面”，而是一个给外贸销售每天使用的 Windows 桌面工作台。用户打开软件时，应该马上感觉到三件事：

1. 我知道自己在哪里。
2. 我知道下一步该做什么。
3. 我相信这个软件能帮我把客户开发这件事完成。

设计目标不是炫技，不是堆卡片，不是把所有能力摆出来。设计目标是把复杂的背调、写信、评分、发送、跟进、学习系统，藏在一个清楚、稳定、可信的工作流后面。

Hermills 的核心句子：

> 输入客户官网和邮箱，Hermills 自动背调客户、匹配公司资料、写出可审核的英文开发信，并帮助用户发送和跟进。

整个 UI 必须围绕这句话服务。

## 1. 用户目标设计

### 1.1 核心用户

Hermills 的主要用户是外贸业务员、外贸老板、小型出口团队、SOHO 外贸从业者。他们通常不是技术用户。他们关心的不是 AI 模型、SMTP、Supabase、Hermes Agent、Scrapling、token 或日志。他们关心的是：

- 能不能快速找到客户。
- 能不能知道客户适合怎么开发。
- 能不能写出不像群发垃圾邮件的开发信。
- 能不能连接自己的邮箱发出去。
- 能不能知道客户有没有回复。
- 能不能批量处理客户，但每一封又像认真写的。

因此 UI 必须避免把技术实现暴露给用户。技术设置可以存在，但必须隐藏在“高级设置”或“诊断”里。

### 1.2 用户核心目标

| 用户目标 | UI 应该怎么支持 |
| --- | --- |
| 快速开始 | 首页提供“写单封开发信”和“批量写开发信”两个明显入口 |
| 准备资料 | 初始化和公司资料页用分步表单，不一次性砸给用户 |
| 配好邮箱 | 用户只填邮箱和授权码，系统自动判断服务商 |
| 背调客户 | 用户不需要选择普通/深度，系统自动自适应深度分析 |
| 写出好邮件 | 邮件结果必须显示主题、正文、评分、证据和修改入口 |
| 批量处理 | 逐条生成，写好一封显示一封 |
| 跟进回复 | 只检查发给客户的邮箱有没有回复，不扫描无关邮件 |
| 远程控制 | 手机或电脑聊天平台扫码绑定后可以发送命令 |

### 1.3 设计判断规则

任何 UI 决策都用下面的问题判断：

- 这个元素是否帮助用户完成客户开发？
- 普通用户能不能看懂？
- 用户点完以后有没有反馈？
- 失败以后用户知道怎么恢复吗？
- 这个信息现在必须显示吗，还是可以藏到高级设置？
- 这个页面有没有一个清楚的主操作？

如果答案不清楚，就应该删、藏、合并或重写。

1. 今日外联

3. 单封写信
4. 批量写信
5. 销售资产

## 3. 核心工作流

### 3.1 单封开发信主流程

流程：

1. 用户进入单封写信。
2. 输入客户邮箱。
3. 输入客户官网。
4. 点击“分析客户官网并生成开发信”。
5. 页面进入 AI 生成中状态。
6. 系统后台执行：抓取官网 -> 提取证据 -> 判断客户类型 -> 匹配公司资料 -> 找开发角度 -> 写邮件 -> 评分 -> 自动重写。
7. 结果区域显示客户简报、证据、主题、正文、评分、修改按钮。
8. 用户保存草稿或发送。

用户表面只看到一个按钮。后台复杂流程不让用户手动选择。

### 3.2 批量开发信主流程

流程：

1. 用户进入批量写信。
2. 上传 Excel / CSV，或粘贴客户列表。
3. 系统解析客户，按“一个邮箱一个客户”建立队列。
4. 每个客户独立执行背调和写信。
5. 写好一封立即出现在结果列表。
6. 失败的客户显示原因，不阻塞其他客户。
7. 用户逐条审核，也可以筛选只看待审核、失败、可发送。

重点：批量不是黑盒等待。它应该像“生产线”，用户随时看到谁在排队、谁在写、谁写好了、谁失败了。

### 3.3 邮箱配置流程

流程：

1. 用户进入邮箱页。
2. 填自己的发件邮箱。
3. 系统根据邮箱后缀自动识别 Gmail、Outlook、腾讯、阿里、Zoho 或自定义。
4. 用户填授权码 / SMTP 密码。
5. 点击“保存并测试邮箱”。
6. 系统测试连接和发信能力。
7. 成功显示“邮箱可用，可以发送开发信”。
8. 失败显示具体原因和下一步。

高级参数默认折叠。普通用户不应该看到 SMTP 主机、端口、API Base URL、token JSON。

### 3.4 聊天控制流程

流程：

1. 用户进入聊天控制。
2. 选择微信、飞书、钉钉、QQ。
3. 点击“生成扫码二维码”。
4. 如果公网绑定地址有效，显示二维码、绑定码、过期时间。
5. 用户扫码。
6. 手机端提示绑定成功。
7. Hermills 显示“连接成功，可以发送：今日状态 / 写开发信 buyer@company.com https://company.com”。
8. 用户发送测试命令。
9. Hermills 显示执行结果。

如果未配置公网地址，按钮不应该生成坏二维码。必须显示：

> 需要先配置云端绑定地址，才能生成手机可扫码二维码。

不允许出现 `undefined/`。

## 4. 页面布局

### 4.1 全局壳层

窗口内容分为三层：

1. 左侧导航：固定宽度 232px。
2. 主内容区：自适应宽度，滚动。
3. 可选右侧详情区：只在客户管理、批量审核等页面出现。

主内容背景：`#f3f7fb`。

主内容最大宽度：根据页面决定。

- 工作台：不限制，使用栅格。
- 单封写信：最大 1120px。
- 邮箱/签名/公司资料：最大 920px。
- 客户管理：使用左右分栏，最大 1280px。

页面 padding：

- 桌面：24px。
- 低高度窗口：20px。
- 窄宽度：16px。

页面标题区：

- H1：28px，700，`#0f172a`。
- 副标题：14px，400，`#52627a`。
- 标题区底部 margin：20px。
- 标题右侧可以放主操作按钮，但只能放 1 个。

### 4.2 页面层级

每个页面从上到下：

1. 页面标题和说明。
2. 全局状态或提醒。
3. 主操作区。
4. 数据或结果区。
5. 次要设置或历史记录。

错误提示不能悬浮盖住内容，必须占据正常文档流。之前那种横跨页面、压住内容的提示条要避免。

### 4.3 响应式规则

虽然只做 Windows 桌面端，也必须支持窗口缩小。

宽度大于 1180px：

- 左侧导航 + 主内容 + 可选详情区。

宽度 920px 到 1180px：

- 客户管理详情区下移。
- 批量页面两栏变一栏。
- 统计卡片使用 2 到 3 列。

宽度小于 920px：

- 左侧导航变顶部横向或折叠抽屉。
- 所有双栏变单栏。
- 按钮可以换行，但文字不能被截断。

高度小于 760px：

- 页面标题区压缩。
- 卡片 padding 从 20px 降到 16px。
- 底部操作条 sticky，保证主按钮可见。

## 6. 设计系统与品牌感

### 6.1 品牌气质

关键词：

- 清楚
- 稳定
- 专业
- 不吓人
- 有智能感但不炫技
- 外贸销售每天愿意打开

Hermills 不应该像开发者控制台，也不应该像玩具式 AI 工具。它应该像一个“懂外贸开发信的销售操作系统”。

### 6.2 字体

Windows 默认：

- 中文：Microsoft YaHei UI / Microsoft YaHei。
- 英文和数字：Inter / Segoe UI。

CSS 字体栈：

```css
font-family: Inter, "Segoe UI", "Microsoft YaHei UI", "Microsoft YaHei", system-ui, sans-serif;
```

字体原则：

- 不使用负字距。
- 不用 viewport width 动态缩放字号。
- 表格和卡片内文字保持 13-14px。
- 页面标题不要超过 30px。

### 6.3 间距系统

基础单位：4px。

常用间距：

- 4px：图标和文字内部微距。
- 8px：小组件内部间距。
- 12px：按钮横向 padding、小卡片 gap。
- 16px：卡片 padding、表单行 gap。
- 20px：大卡片 padding。
- 24px：页面 padding。
- 32px：页面大区块之间距离。

不能随手写 13px、17px、23px 这种没有体系的间距，除非为了视觉微调有明确原因。

### 6.4 圆角

- 小按钮、小输入框：8px。
- 卡片：10px。
- 大容器：12px。
- 胶囊状态：999px。
- 弹窗：14px。

卡片不使用过大的 20px+ 圆角，避免显得像移动端玩具。

### 6.5 阴影

普通卡片：

```css
box-shadow: 0 1px 2px rgba(15, 23, 42, 0.06);
```

浮层 / 弹窗：

```css
box-shadow: 0 18px 50px rgba(15, 23, 42, 0.18);
```

主按钮 hover 可以使用轻微蓝色阴影：

```css
box-shadow: 0 8px 18px rgba(37, 99, 235, 0.20);
```

不要滥用大阴影。B2B 工具要稳，不要漂。

## 7. 组件系统

### 7.1 按钮

按钮是 Hermills 最重要的行动信号。每个页面只能有一个最强主按钮。

#### 主按钮

用途：生成开发信、保存并测试邮箱、批量生成、保存公司资料。

样式：

- 高度：40px。
- 最小宽度：120px。
- 圆角：8px。
- 背景：`#2563eb`。
- hover 背景：`#1d4ed8`。
- active 背景：`#1e40af`。
- disabled 背景：`#d9e2ef`。
- disabled 文字：`#64748b`。
- 文字：14px，700，白色。
- 图标：16px，stroke 2px，放左侧或右侧。
- 图标和文字间距：8px。

主按钮文案必须具体：

- 好：`分析客户官网并生成开发信`
- 好：`保存并测试邮箱`
- 好：`选择文件并生成开发信`
- 差：`提交`
- 差：`开始`

#### 次按钮

用途：打开详情、返回、只导入客户、复制、预览。

样式：

- 高度：38px。
- 背景：白色。
- 边框：1px `#cbd8e8`。
- 文字：`#1e3a5f`。
- hover 背景：`#f8fbff`。
- hover 边框：`#93c5fd`。

#### 危险按钮

用途：删除客户、删除 Logo、移除账号。

样式：

- 背景：白色。
- 边框：1px `#fecaca`。
- 文字：`#b91c1c`。
- hover 背景：`#fef2f2`。

#### 幽灵按钮

用途：折叠展开、查看日志、复制详情。

样式：

- 背景：透明。
- 文字：`#2563eb`。
- hover 背景：`#eff6ff`。
- 高度：32px。

#### 图标按钮

用途：关闭、编辑、复制、更多。

样式：

- 尺寸：32px x 32px。
- 圆角：8px。
- 默认背景：透明。
- hover 背景：`#edf6ff`。
- 图标：16px。
- 必须有 tooltip 或 aria-label。

#### 加载中的按钮

按钮 loading 时：

- 保持原宽度，不跳动。
- 左侧图标替换为 14px spinner。
- spinner 使用 1.8px stroke。
- 动画：线性旋转，0.8s 一圈。
- 文案变成明确动作，例如：
  - `正在分析客户官网...`
  - `正在保存并测试...`
  - `正在导入客户...`

不要只显示一个转圈。

### 7.2 输入框

用途：邮箱、官网、公司名、授权码、搜索。

样式：

- 高度：42px。
- 圆角：8px。
- 背景：白色。
- 边框：1px `#cbd8e8`。
- 文字：14px，`#0f172a`。
- placeholder：`#94a3b8`。
- padding：0 12px。
- focus 边框：`#2563eb`。

错误状态：

### 7.3 文本域

用途：邮件正文、公司资料、签名、批量粘贴客户。

### 7.4 卡片

卡片用于承载一个独立任务，不用于包裹整个页面。

普通卡片：

- 背景：白色。
- 边框：1px `#d8e2f0`。
- 圆角：10px。
- padding：20px。
- 阴影：轻微。

卡片标题：

- 左侧图标 18px。
- 标题 16px，700。
- 下方说明 13px。

卡片内部不能再套大卡片。可以用分隔线或浅色区块。

### 7.5 统计卡片

用于今日外联、批量写信、销售资产。

尺寸：

- 高度：96px。
- padding：18px。
- 右侧图标容器：36px x 36px。

内容：

- 上方 label：13px，600，`#52627a`。
- 数字：28px，800，`#0f172a`。
- 小说明：12px，`#64748b`。

图标色：

- 总客户：蓝。
- 待生成：紫。
- 待发送：橙。
- 等待回复：紫蓝。
- 已回复：绿。

### 7.6 表格 / 列表

客户管理优先使用列表式表格，不用密密麻麻传统表格。

行高：

- 普通行：72px。
- 紧凑行：60px。

行结构：

左侧：复选框 + 客户图标。

中间：公司名、邮箱、官网。

右侧：邮件状态、质量分、最近更新时间。

选中状态：

- 边框：`#8b5cf6` 或主蓝。
- 背景：`#f8fbff`。

hover：

- 背景：`#f8fbff`。

状态点：

- 待生成：灰。
- 生成中：蓝。

## 8. 交互反馈

### 8.1 点击反馈

所有可点击元素必须有 hover 和 active。

按钮点击时：

- active 下沉 1px 或变深色。
- 不使用夸张缩放。

卡片可点击时：

- cursor pointer。
- hover 边框变蓝。
- hover 背景轻微变亮。

### 8.2 保存反馈

保存成功：

- 右上或页面内显示绿色提示条。
- 文案：`已保存。之后生成的开发信会自动使用这份资料。`

保存失败：

- 红色提示条。
- 文案包含原因和下一步。

### 8.3 删除反馈

删除必须确认：

标题：`删除这个客户？`

正文：`删除后会移除客户资料和关联草稿，但不会删除已经发送的邮箱记录。`

按钮：`取消`、`删除客户`。

### 8.4 AI 生成反馈

AI 生成不能让用户盯着一个按钮等。

必须显示：

- 当前正在做什么。
- 已完成什么。
- 如果超过 20 秒，显示“还在分析，这通常发生在客户网站页面较多时”。
- 如果失败，显示自动降级或失败原因。

失败文案示例：

> 深度抓取失败，Hermills 已改用轻量抓取继续生成。你仍然可以查看证据来源。

### 8.5 批量任务反馈

批量任务必须逐条完成。

每个客户行状态：

- 排队中
- 正在背调
- 正在写信
- 待审核
- 可发送
- 失败

状态变化时行内有轻微背景闪烁：

- 完成：浅绿闪 400ms。
- 失败：浅红闪 400ms。

## 9. 状态设计

### 9.1 默认状态

页面有数据时，默认状态必须显示最有用的信息，而不是展示所有字段。

例如客户管理默认展示：

- 最近更新时间

### 9.2 空状态

样式：

- 居中或卡片内。
- 图标 40px。
- 标题 16px，700。
- 说明 14px。
- 主按钮。

客户空状态：

标题：`还没有客户`

说明：`输入一个客户官网和邮箱，Hermills 会自动背调并生成第一封开发信。`

按钮：`写第一封开发信`

批量空状态：

标题：`还没有批量任务`

说明：`上传 Excel / CSV，或者直接粘贴客户邮箱和官网。`

按钮：`选择客户文件`

### 9.3 加载状态

见 7.11。

### 9.4 成功状态

成功状态要告诉用户结果和下一步。

例：

`已生成开发信草稿。请审核邮件内容，确认后再发送。`

### 9.5 失败状态

失败状态必须包括：

1. 人话原因。
2. 下一步。
3. 技术详情折叠。

## 10. 表单与输入体验

### 10.1 表单原则

- 必填字段尽量少。
- 能自动识别就不要用户选择。
- 能从官网背调得到的信息，不强迫用户手填。
- 长表单必须分组。
- 每个字段都要有示例。

### 10.2 单封写信表单

字段：

1. 客户邮箱
2. 客户网站

可选字段折叠：

- 联系人姓名
- 客户备注

客户邮箱：

- placeholder：`buyer@company.com`
- 输入错误提示：`请输入有效邮箱，例如 buyer@company.com`

客户网站：

- placeholder：`https://company.com`
- 用户粘贴 `company.com` 时自动补 `https://`。

主按钮：

`分析客户官网并生成开发信`

按钮可用条件：

- 邮箱合法。
- 官网看起来是 URL。

### 10.3 批量导入表单

支持：

- `.xlsx`
- `.xls`
- `.csv`
- `.txt`
- 直接粘贴

拖拽区：

- 高度：180px。
- 虚线边框。
- 中央图标。
- 文案：`点击或拖拽上传 Excel / CSV 文件`
- 辅助：`每一行至少包含邮箱；如果有官网，开发信会更精准。`

粘贴框 placeholder：

```text
buyer@example.com, https://example.com, John Smith

```

导入后预览：

- 显示识别客户数。
- 显示缺官网数量。

### 10.4 邮箱配置表单

普通模式字段：

1. 发件邮箱
2. 邮箱授权码 / SMTP 密码

- SMTP 主机
- SMTP 端口

- API 通道
- API token
- IMAP 设置

高级设置标题：

`高级设置（一般不用管）`

### 10.5 签名 Logo 表单

字段：

1. 文字签名
2. Logo 上传

文字签名 placeholder：


- 最大 2MB。
- 上传后显示预览。

`保存签名和 Logo`

不显示：

- HTML 签名
- Logo 宽度
- Logo 替代文字
- 自动追加开关

默认逻辑：只要有文字签名或 Logo，就自动追加到开发信。

## 11. 文案系统

### 11.1 文案原则

- 用用户语言，不用工程语言。
- 按钮写动作结果，不写“提交”。
- 错误写恢复方法，不写纯错误码。
- 空状态写下一步。
- 成功状态写下一步。

### 11.2 常用按钮文案

| --- | --- |

| 审核通过 | 标记为可发送 |

### 11.3 错误文案

坏文案：

`本地服务：Hermes 没能完成这次请求。`

改成：

`Hermills 暂时没有完成生成。请先重试一次；如果还失败，复制详情给技术支持。`

坏文案：

`SMTP auth failed`

改成：

`邮箱授权失败。请确认你填写的是邮箱授权码，不是登录密码。`

坏文案：

`undefined relay URL`

改成：

`还不能生成扫码二维码。请先配置云端绑定地址。`

生成前：

`Hermills 会自动读取客户官网，提取业务线索，再结合你的公司资料写一封可审核的英文开发信。`

`已生成开发信草稿。请先审核内容，确认后再发送。`

低分邮件：

`这封邮件还不适合发送，Hermills 会自动重写。`

高分邮件：

`这封邮件已达到发送标准，请确认客户信息和签名。`

## 14. 动效规范

### 14.1 基础原则

动效只用于反馈，不用于装饰。

时间：

- hover 过渡：120ms。
- 卡片进入：180ms。
- 弹窗进入：160ms。
- loading spinner：800ms 一圈。
- skeleton shimmer：1200ms。

缓动：

```css
cubic-bezier(0.2, 0.8, 0.2, 1)
```

### 14.2 页面切换

页面切换：

- 内容区域淡入 120ms。
- 不做大幅滑动，避免桌面工具显得轻浮。

### 14.3 AI 生成中

步骤完成：

- 圆点从蓝色 spinner 变绿色 check。
- 文案不跳动。
- 当前步骤轻微蓝底。

### 14.4 批量逐条完成

新结果出现：

- opacity 0 -> 1。
- translateY 6px -> 0。
- 时间 180ms。

失败结果：

- 背景轻微红闪一次。

### 14.5 按钮加载

按钮 spinner：

```css
@keyframes spin {
  to { transform: rotate(360deg); }
}
```

按钮宽度固定，不能因为文案变化导致布局跳。

## 15. 可访问性

- 所有按钮必须有可读文字或 aria-label。
- 图标按钮必须有 tooltip。
- 表单 label 必须和 input 绑定。
- 错误提示要和字段关联。
- 颜色不能作为唯一状态表达，还要有文字。
- 焦点态必须明显。
- 键盘 Tab 顺序必须符合页面视觉顺序。
- 禁用按钮不应完全灰掉到不可读。

## 17. 最终判断标准

Hermills UI 重做成功，不是因为它更漂亮，而是因为用户能做到：

- 一眼知道今天要干什么。
- 第一次使用不会卡在初始化。
- 配邮箱时不需要懂 SMTP。
- 写单封开发信只需要输入邮箱和官网。
- 批量任务不用等全部完成才看到结果。
- 每封邮件都有证据、评分和可编辑正文。
- 错误出现时知道怎么恢复。
- 软件看起来稳定、专业、值得把客户资料交给它。

这份规格是后续实现的设计合同。任何 UI 改动如果违反这份规格，就算视觉上更花，也不能合并。

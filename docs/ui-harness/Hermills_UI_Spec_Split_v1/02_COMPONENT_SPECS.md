# 02_COMPONENT_SPECS.md

文档定位：Hermills 的组件施工规格。  
适用对象：组件实现 Agent、前端工程师、Codex、验收 Agent。  
依赖文件：先读 `00_UI_MAP.md` 和 `01_VISUAL_SYSTEM.md`，再读本文件。  
本文件专门写按钮、输入框、卡片、表格、Badge、弹窗、提示条、加载、空状态和错误状态。

---

# 1. 组件总原则

Hermills 的组件不是孤立好看的 UI 零件，而是外贸销售工作流中的行动信号。每个组件都必须让用户更快理解页面、更快完成客户开发、更少接触技术概念、更容易从错误中恢复。

组件必须统一。不能每个页面自己写一套按钮、输入框、卡片、提示条和状态标签。能复用的必须抽成复用组件。实现 Agent 不得为了快速完成页面而复制粘贴同一套样式到多个地方。

所有组件必须有默认状态、hover 状态、active 状态、disabled 状态、loading 状态或对应的不可用状态。所有涉及失败的组件必须提供人话原因和下一步动作。

---

# 2. 主按钮 Primary Button

主按钮是 Hermills 中最重要的行动信号。它不是一个普通蓝色块，而是一个让用户相信“点下去软件会开始工作”的启动控制键。

主按钮用于以下动作：分析客户官网并生成开发信，选择文件并生成开发信，保存并测试邮箱，发送开发信，保存公司资料，保存签名和 Logo，进入 Hermills，重写到 80 分以上。

视觉形态：主按钮高度 40px 到 44px，最小宽度 120px，左右 padding 16px 到 20px，圆角 8px 到 10px。背景默认 #2563eb，hover #1d4ed8，active #1e40af。文字白色，14px，700。图标 16px，stroke 2px，放在文字左侧或右侧。图标和文字间距 8px。

质感描述：主按钮应该像页面里的启动键。它安静但明确，不发光、不跳动、不炫耀。它在白色卡片和浅灰蓝背景中成为最自然的下一步。hover 时蓝色稍深，阴影轻微增强，按钮像被唤醒一样微微浮起 1px。active 时按钮下压 1px，阴影收回，颜色变深，让用户感觉点击被软件接住。

loading 状态：按钮必须保持原宽度，不因为文案变化导致布局跳动。左侧图标替换为 14px spinner，spinner stroke 1.8px，0.8s 一圈。文案必须是具体动作，例如“正在分析客户官网...”“正在保存并测试...”“正在导入客户...”“正在发送开发信...”。不允许只显示“处理中”或只显示一个转圈。

disabled 状态：背景 #d9e2ef，文字 #64748b，无阴影，hover 无变化。禁用按钮旁边或下方必须有轻提示，告诉用户为什么不能点。例如“请输入有效邮箱和客户官网后开始分析”。

文案规则：好文案是“分析客户官网并生成开发信”“保存并测试邮箱”“选择文件并生成开发信”“重写到 80 分以上”“保存到客户档案”。坏文案是“提交”“确认”“开始”“生成”“下一步”。按钮文案必须让用户知道点完以后发生什么。

验收点：每个页面或每个明确任务区只能有一个最强主按钮。多个蓝色主按钮同时出现时，验收失败。

# 3. 次按钮 Secondary Button

次按钮用于辅助动作，例如返回、复制、预览、打开详情、重新测试、仅导入客户、查看证据、取消。

样式：高度 38px，圆角 8px，背景白色，边框 1px #cbd8e8，文字 #1e3a5f，14px，600。hover 背景 #f8fbff，hover 边框 #93c5fd。active 背景 #eff6ff。

次按钮不应该抢主按钮的注意力。它应该像一个清楚的辅助入口，而不是第二个主流程。

---

# 4. 危险按钮 Danger Button

危险按钮用于删除客户、删除 Logo、断开邮箱、清空草稿、移除账号。

样式：背景白色，边框 1px #fecaca，文字 #b91c1c。hover 背景 #fef2f2。active 背景 #fee2e2。

危险按钮不能直接执行破坏性操作。点击后必须弹出确认弹窗，说明操作影响。危险操作按钮通常放在确认弹窗右下角最右侧。业务页面中不要让危险按钮和主按钮并列抢注意力。

---

# 5. 幽灵按钮 Ghost Button

幽灵按钮用于低权重动作，例如查看日志、展开高级设置、复制详情、折叠区域、查看生成过程、更多信息。

样式：高度 32px，背景透明，文字 #2563eb，hover 背景 #eff6ff，圆角 8px。文字 13px 到 14px，600。

幽灵按钮不能承载关键动作。不能把“发送开发信”“保存并测试邮箱”“分析客户官网”做成幽灵按钮。

---

# 6. 图标按钮 Icon Button

图标按钮用于关闭、编辑、复制、更多、展开、收起、删除、刷新。

样式：尺寸 32px x 32px，圆角 8px，默认背景透明，hover 背景 #edf6ff，active 背景 #dff0ff，图标 16px。

每个图标按钮必须有 tooltip 或 aria-label。只有图标没有文字时，用户也必须知道它的作用。删除类图标按钮必须使用红色 hover 或确认弹窗，不能误触。

---

# 7. 输入框 Input

输入框用于客户邮箱、客户官网、公司名、授权码、搜索、显示名称、测试收件箱。

样式：高度 42px，圆角 8px，白底，边框 1px #cbd8e8，文字 14px #0f172a，placeholder #94a3b8，padding 0 12px。focus 边框 #2563eb，focus 阴影 `0 0 0 3px rgba(37, 99, 235, 0.12)`。

错误状态：边框 #ef4444，focus 阴影 `0 0 0 3px rgba(239, 68, 68, 0.12)`，字段下方显示 13px 错误文案。错误文案必须告诉用户怎么改，例如“请输入有效邮箱，例如 buyer@company.com”。

成功状态：边框 #10b981，右侧可以显示绿色 check。成功状态不要过度强调，不要整块输入框变绿色。

客户邮箱输入：placeholder 为 `buyer@company.com`。输入不合法时提示“请输入有效邮箱，例如 buyer@company.com”。

客户网站输入：placeholder 为 `https://company.com`。用户粘贴 `company.com` 时自动补 `https://`。输入不合法时提示“请输入客户官网，例如 https://company.com”。

搜索输入：placeholder 为“搜索公司、邮箱、联系人...”。搜索框左侧可以有 16px 放大镜图标。搜索框不应像主操作按钮一样抢眼。

授权码输入：默认隐藏内容，右侧有眼睛图标切换显示。字段下方提示“请填写邮箱授权码或应用专用密码，不是邮箱登录密码”。如果识别为 Gmail，显示“已识别为 Gmail。请填写 Gmail 应用专用密码”。

---

# 8. 文本域 Textarea

文本域用于邮件正文、公司资料、文字签名、客户备注、批量粘贴客户。

样式：白底，边框 #cbd8e8，圆角 8px，padding 12px，字号 14px，行高 1.65，resize vertical。普通文本域最小高度 120px。邮件正文编辑区最小高度 260px。批量粘贴区最小高度 180px。

邮件正文文本域需要舒服的阅读宽度，最大宽度建议 720px，不能横向拉得太长。邮件正文区域要像一个可审核的邮件编辑器，而不是普通备注框。它可以使用更清晰的行高、轻微内阴影或白底边框来表现可编辑。

批量粘贴框 placeholder：

```text
buyer@example.com, https://example.com, John Smith
another@company.com, https://company.com
```

---

# 9. 文件拖拽区 Upload Dropzone

拖拽区用于批量写信上传 Excel、CSV、TXT 文件。

样式：高度 180px，圆角 12px，白底或极浅蓝背景，虚线边框 1.5px #cbd8e8，中央放 40px 上传图标。标题 15px 700，说明 13px #64748b。

默认文案：“点击或拖拽上传 Excel / CSV 文件”。辅助文案：“每一行至少包含邮箱；如果有官网，开发信会更精准。”

hover 状态：边框 #93c5fd，背景 #f8fbff。拖拽进入状态：边框 #2563eb，背景 #eff6ff。上传中状态：显示进度或解析中说明。解析失败状态：显示红色提示条和“重新选择文件”按钮。

支持格式必须显示为 `.xlsx`、`.xls`、`.csv`、`.txt`。如果格式不支持，提示“暂不支持这个文件格式。请上传 Excel、CSV 或 TXT 文件。”

---

# 10. 普通卡片 Card

卡片用于承载一个独立任务或信息组，不用于无意义地包裹整个页面。

样式：白底，边框 1px #d8e2f0，圆角 10px，padding 20px，轻微阴影 `0 1px 2px rgba(15, 23, 42, 0.06)`。

卡片标题区可以包含左侧图标、标题和说明。图标 18px，标题 16px 700，说明 13px #64748b。卡片内部不能再套大卡片。如果需要分组，用分隔线、浅色区块或小节标题。

可点击卡片需要 cursor pointer，hover 边框变 #93c5fd，背景 #f8fbff。不可点击卡片不要有强 hover。

---

# 11. 任务卡 Task Card

任务卡用于今日外联快捷入口，例如写单封开发信、整理客户、批量写开发信、检查邮箱。

样式：白底，边框 #d8e2f0，圆角 12px，padding 18px，hover 边框 #93c5fd，hover 背景 #f8fbff，active 轻微下压。图标容器 36px x 36px，浅蓝底，圆角 10px，图标 18px。标题 15px 700，说明 13px。

任务卡要像可以点击的工作入口，不像普通设置项。点击后应该进入对应流程，不要弹出无意义弹窗。

---

# 12. 统计卡 Metric Card

统计卡用于今日外联、批量任务、客户状态概览。

样式：高度 96px，白底，边框 #d8e2f0，圆角 10px，padding 18px。右侧图标容器 36px x 36px。上方 label 13px 600 #52627a，数字 28px 800 #0f172a，小说明 12px #64748b。

数字是视觉焦点，图标不能抢数字。统计卡不应该像广告卡或彩色大块，它应该稳定、清楚、可扫读。

---

# 13. 客户列表行 Customer Row

客户列表优先使用列表式表格，不用密密麻麻传统表格。

行高：普通 72px，紧凑 60px。结构从左到右为复选框、客户图标、公司名或邮箱、邮箱和官网、客户状态、邮件状态、质量分、最近更新时间、更多按钮。

hover 背景 #f8fbff。选中状态背景 #f8fbff，并有蓝色左边线或边框强调。失败状态只用 badge、提示文字和错误图标，不要整行大红。客户官网应该可点击或可复制，但不要让蓝色链接过多影响主状态。

---

# 14. Badge / Status Pill

Badge 用于表达状态，不用于可点击操作。

样式：高度 24px，padding 0 8px，圆角 999px，字号 12px，字重 700。

准备好：浅绿底绿字。待处理：浅灰底灰字。生成中：浅蓝底蓝字。需要审核：浅黄底黄字。失败：浅红底红字。高质量：浅绿底。需要重写：浅黄底。已发送：浅绿底。等待回复：浅蓝紫底。已回复：浅紫底。

不可点击的 Badge 不能有强 hover。Badge 的颜色必须配合文字表达，不能只靠颜色区分状态。

---

# 15. 提示条 Alert

提示条必须在文档流里出现，不允许悬浮遮挡页面内容。

成功提示：背景 #ecfdf5，边框 #a7f3d0，文字 #047857。警告提示：背景 #fff7ed，边框 #fed7aa，文字 #9a3412。错误提示：背景 #fef2f2，边框 #fecaca，文字 #b91c1c。信息提示：背景 #eff6ff，边框 #bfdbfe，文字 #1d4ed8。

提示条结构：左侧状态图标，中间标题和说明，右侧可选动作按钮。错误提示必须包含下一步动作，例如复制详情、打开邮箱设置、重试、查看诊断、查看获取授权码方法。

坏错误文案：“SMTP auth failed”。好错误文案：“邮箱授权失败。请确认你填写的是邮箱授权码，不是登录密码。”

---

# 16. 弹窗 Modal

弹窗用于删除确认、发送确认、详情预览、失败诊断、授权码帮助。

样式：宽度 440px 到 680px，圆角 14px，白底，overlay rgba(15, 23, 42, 0.38)，padding 24px，阴影 `0 18px 50px rgba(15, 23, 42, 0.18)`。

结构：标题、说明、主要内容、底部按钮区。底部按钮右对齐。危险操作必须在最右，且颜色红。关闭按钮在右上角，必须有 aria-label。

删除客户弹窗示例：标题“删除这个客户？”。正文“删除后会移除客户资料和关联草稿，但不会删除已经发送的邮箱记录。”按钮“取消”和“删除客户”。

发送确认弹窗示例：标题“发送这封开发信？”。正文提醒用户确认收件人、主题、正文和签名。主按钮“确认发送”。

---

# 17. 抽屉 Drawer

抽屉用于客户详情、邮件详情、批量结果详情、证据详情。

桌面宽度 420px 到 520px，右侧滑出，白底，左侧边框 #d8e2f0，头部 sticky，底部操作条 sticky，内容区域滚动。窄屏时抽屉可变成全屏。

抽屉不应该承载完整复杂流程。它适合查看和轻量编辑，不适合让用户在里面完成所有设置。

---

# 18. AI 生成时间线 AI Progress Timeline

AI 生成不能只显示一个 spinner。Hermills 必须告诉用户当前正在做什么、完成了什么、如果失败如何降级。

时间线步骤建议为：正在读取客户官网，正在提取业务线索，正在匹配公司资料，正在选择开发角度，正在生成开发信，正在进行质量检查，正在保存草稿。

等待步骤使用灰色圆点，当前步骤使用蓝色 spinner，完成步骤使用绿色 check，失败但已降级使用黄色警告。当前步骤行有浅蓝背景。完成步骤文字变为 #047857。等待步骤文字为 #64748b。

超过 20 秒时显示补充说明：“还在分析，这通常发生在客户网站页面较多时。”如果深度抓取失败但轻量抓取继续，显示：“深度抓取失败，Hermills 已改用轻量抓取继续生成。你仍然可以查看证据来源。”

详细技术过程默认折叠，按钮为“查看生成过程”。业务用户第一眼只看人话进度。

# 19. 质量评分卡 Quality Score Card

质量评分卡是邮件结果的信任锚点。

显示内容：总分 0 到 100、大号数字、状态标签、维度评分、风险提醒、下一步建议。

分数规则：90-100 为优秀，深绿，状态“优秀”。80-89 为可发送，绿色，状态“可发送”。60-79 为建议修改，黄色，状态“建议修改”。0-59 为不能发送，红色，状态“不能发送”。

维度建议：客户相关性、自然度、具体性、CTA 合理性、风险控制、长度控制。每个维度用短文案，不要长篇解释。

低于 80 分时，默认主按钮不是“发送开发信”，而是“重写到 80 分以上”。发送按钮可以存在，但必须降级并要求确认。

---

# 20. 证据来源卡 Evidence Card

证据来源卡用于告诉用户 AI 为什么这样写。

每条证据显示页面标题、URL、提取到的证据句、这条证据被用在哪里。不要展示整段网页原文。不要让用户在结果页看到大段抓取文本。

证据卡样式：浅蓝或白底小卡，边框 #d8e2f0，圆角 8px，padding 12px。URL 使用 12px #2563eb，证据句使用 13px #31445f，作用说明使用 12px #64748b。

如果证据不足，显示警告：“客户官网可用信息较少，这封邮件会更保守。建议人工补充客户类型或产品方向。”

---

# 21. 空状态 Empty State

空状态必须告诉用户下一步，不能只显示空白。

样式：居中或卡片内，图标 40px，标题 16px 700，说明 14px，主按钮一个。空状态背景可用白色卡片或浅蓝灰区域。

客户空状态标题“还没有客户”。说明“输入一个客户官网和邮箱，Hermills 会自动背调并生成第一封开发信。”按钮“写第一封开发信”。

批量空状态标题“还没有批量任务”。说明“上传 Excel / CSV，或者直接粘贴客户邮箱和官网。”按钮“选择客户文件”。

邮件结果空状态标题“还没有生成开发信”。说明“输入客户邮箱和官网后，Hermills 会自动生成一封可审核的英文开发信。”按钮“开始写信”。

---

# 22. 加载状态 Loading State

页面加载使用 skeleton，不用大转圈。Skeleton 背景 #e8eef6，圆角 8px，动画 1.2s shimmer。

操作加载使用按钮内部 spinner + 具体文案。AI 生成中使用任务时间线。批量任务加载使用队列状态，不使用整页遮罩。

加载状态不得让用户不知道软件是否卡住。超过一定时间必须显示说明。失败后必须切换到可恢复错误状态。

---

# 23. 错误状态 Error State

错误状态必须包含三部分：人话原因、下一步动作、技术详情折叠。

人话原因告诉用户发生了什么。下一步动作告诉用户怎么恢复。技术详情折叠给技术支持或高级用户使用。

错误状态示例：标题“邮箱测试失败”。说明“Gmail 拒绝了这个授权码。请确认你填写的是应用专用密码，不是 Gmail 登录密码。”主按钮“查看获取授权码方法”。次按钮“复制技术详情”。折叠区标题“技术详情”。

业务页面不显示 raw stack trace。系统设置或诊断页面可以完整显示技术日志。

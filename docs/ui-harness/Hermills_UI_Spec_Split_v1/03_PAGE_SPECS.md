# 03_PAGE_SPECS.md

文档定位：Hermills 的页面级 UI 施工规格。  
适用对象：页面实现 Agent、Codex、前端工程师、验收 Agent。  
依赖文件：先读 `00_UI_MAP.md`、`01_VISUAL_SYSTEM.md`、`02_COMPONENT_SPECS.md`。  
本文件专门写登录注册、初始化、今日外联、客户管理、单封写信、批量写信、邮箱配置、签名 Logo、公司资料、聊天控制、系统设置。

---

# 1. 页面规格统一模板

每个页面都必须按照同一个思路实现：页面目标、用户第一眼画面、布局结构、核心组件、默认状态、空状态、加载状态、成功状态、失败状态、交互行为、文案规则、禁止事项、验收标准。

实现 Agent 不得只做默认态。每个核心页面至少要实现默认、空、加载、成功、失败五类状态。涉及权限、网络、AI 降级、批量部分完成的页面，还要实现对应特殊状态。

---

# 2. 登录注册页面

页面目标：让用户安全进入 Hermills，同时建立信任。登录注册页面不只是账号入口，它应该告诉用户：Hermills 会同步客户记录和邮件草稿，但真实邮箱密码和 API Key 仍然只保存在本机。

用户第一眼画面：浅蓝灰背景铺满窗口。页面中央是一张 440px 宽的白色卡片，圆角 16px，轻微阴影。卡片上方有 Hermills 品牌图标和品牌名。卡片内容垂直居中但不拥挤。用户第一眼看到标题“创建 Hermills 账号”或“账号登录”，然后看到简短说明和输入框。

布局结构：页面背景 #eef5fc。中央卡片最大宽 440px。卡片 padding 28px。卡片顶部有 32px 品牌图标，下面是标题和说明。输入区按垂直表单排列，字段间距 14px 到 16px。底部是主按钮和次链接。

注册卡片内容：图标可以是钥匙或邮箱。小标题“账号登录”。大标题“创建 Hermills 账号”。说明“登录后会同步客户记录、邮件草稿和匿名学习数据。真实邮箱密码和 API Key 仍然只保存在本机。”字段为姓名、邮箱、密码。主按钮“注册并获取验证码”。次链接“已有账号，去登录”。

验证码卡片内容：标题“输入邮箱验证码”。说明“我们已向 {email} 发送 6 位验证码。”输入框可以是 6 个数字格，也可以是一个 6 位数字输入框。主按钮“验证并登录”。次按钮“重新发送验证码”。倒计时文案“56 秒后可重新发送”。

错误状态：邮箱已注册时显示“这个邮箱已经注册，请直接登录。”验证码错误时显示“验证码不正确，请检查邮件里的 6 位数字。”验证码过期时显示“验证码已过期，请重新发送。”网络异常时显示“暂时无法连接账号服务，请检查网络后重试。”

禁止事项：不要展示 Supabase、JWT、session、token、auth provider 等技术词。不要在登录页放太多营销内容。不要用大面积渐变和插画抢表单注意力。

验收标准：注册、登录、验证码、错误、loading、禁用按钮、密码显示切换都要有清楚状态。输入错误必须出现在字段下方，不悬浮遮挡。

# 3. 初始化向导页面

页面目标：让第一次使用的用户逐步填写影响写信质量的基础资料，不要一次性把所有字段砸给用户。

用户第一眼画面：左侧是 240px 步骤栏，显示 10 个初始化步骤。右侧是白色主表单区，顶部显示“第 X 步，共 10 步”，下面是当前任务标题和解释。底部有 sticky 操作条，左边“上一步”，右边“继续”，最后一步为“进入 Hermills”。

布局结构：窗口背景 #f3f7fb。左侧步骤栏固定，白底，右侧边框。右侧内容区最大 760px，padding 24px。表单卡片白底，圆角 10px，padding 24px。底部操作条 sticky，白底，上边框 #d8e2f0。

步骤：语言、名字、公司、产品、客户、优势、交易、资料、路径、确认。每一步字段不超过 4 个，超过必须拆分。每个字段都要有示例。

步骤视觉：当前步骤蓝色圆点和深色文字。已完成步骤绿色 check。未完成步骤灰色圆点。左侧步骤栏要让用户知道还有多少步，不要制造迷路感。

确认页：不要再展示一堆可编辑字段，而是用摘要卡片显示公司名、官网、主营产品、目标客户、优势、交易信息、签名状态。每个摘要卡片有“修改”幽灵按钮，可跳回对应步骤。

成功状态：最后一步点击“进入 Hermills”后显示“资料已保存。之后生成的开发信会自动使用这些信息。”然后进入今日外联。

失败状态：保存失败时显示人话错误，例如“公司资料暂时没有保存成功。请先重试一次；如果还失败，复制详情给技术支持。”按钮“重试保存”和“复制详情”。

禁止事项：不要把所有公司资料字段放到一个页面。不要让用户填写 SMTP、API Key、模型参数。初始化只收集写信必要资料。

# 4. 今日外联页面

页面目标：这是 Hermills 的工作台首页，帮助用户知道今天要处理什么，并快速进入单封写信、批量写信、客户整理和邮箱检查。

用户第一眼画面：左侧导航中“今日外联”高亮。主内容区顶部左侧是 H1“今日外联”，副标题“查看今天要处理的客户、草稿、发送和回复”。右上角只有一个主按钮“写单封开发信”。标题下方是一排统计卡，再下面是快捷任务卡和待处理任务区。

布局结构：主内容区 padding 24px。标题区 margin-bottom 20px。统计卡在宽屏下 5 列，窄屏下 2 到 3 列。快捷任务卡在宽屏下 4 列，窄屏下 2 列或 1 列。待处理区使用白色卡片，不做复杂图表。

统计卡：总客户、待生成、待发送、等待回复、已回复。每张卡显示 label、大数字、小说明和线性图标。数字是焦点。

快捷任务：写单封开发信、整理客户、批量写开发信、检查邮箱。每个任务卡有图标、标题、说明和 hover 状态。点击进入对应页面。

默认状态：如果有客户和任务，显示统计和待处理列表。待处理列表优先显示待审核邮件、待发送邮件、失败需要处理、等待回复客户。

空状态：如果没有客户，显示“今天还没有外联任务。输入客户官网和邮箱，生成第一封开发信。”按钮“写第一封开发信”。空状态应该在主卡片内，不要整页空白。

警告状态：如果邮箱未连接，显示黄色提示条“还没有可用发件邮箱。连接邮箱后才能直接发送开发信。”按钮“去配置邮箱”。

禁止事项：不要把今日外联做成 BI 大屏。不要堆复杂图表。不要把系统日志和模型状态放在首页。首页的目标是启动每日工作，不是展示所有能力。

# 5. 客户管理页面

页面目标：让用户查看、筛选、审核和跟进客户。客户管理应该像外贸客户工作队列，不是传统密集 CRM 表格。

用户第一眼画面：页面顶部是标题“客户”，副标题“管理客户资料、邮件草稿和跟进状态”。标题右侧可以有一个主按钮“新增客户”或“写单封开发信”。标题下方是搜索框和状态筛选。页面主体左侧是客户列表，右侧是客户详情面板。

布局结构：宽屏下左侧列表 46%，右侧详情 54%。整体最大宽 1280px。列表和详情都是白色卡片。列表区域内部滚动，详情面板内部滚动，底部操作条 sticky。窄屏下详情下移或变抽屉。

搜索和筛选：搜索框 placeholder 为“搜索公司、邮箱、联系人...”。筛选按钮包括全部、新客户、待发送、已发送、已回复、失败。筛选按钮用 pill 样式，当前筛选浅蓝底。

客户列表行：显示公司名或邮箱、邮箱、官网、客户状态、邮件状态、质量分、最近更新时间。选中行浅蓝背景并有左侧蓝色强调。失败行显示红色 badge 和“查看原因”幽灵按钮。

详情面板：顶部显示客户名、邮箱、官网、状态。下面分区为客户基本信息、客户背调摘要、证据来源、开发角度、邮件主题、可编辑邮件正文、质量评分、历史记录。邮件正文区域可编辑。质量评分在正文下方或右侧。底部 sticky 操作按钮为保存修改、重新生成、发送。

空状态：没有客户时显示“还没有客户。输入一个客户官网和邮箱，Hermills 会自动背调并生成第一封开发信。”按钮“写第一封开发信”。

详情空态：未选择客户时，右侧显示“选择一个客户查看详情”，说明“你可以查看客户背调、邮件草稿、证据来源和跟进记录。”

失败状态：客户背调失败时，在详情顶部显示红色提示条，说明人话原因和下一步。技术详情折叠。

禁止事项：不要用密密麻麻传统表格作为唯一展示方式。不要在列表里展示过多字段。不要把原始抓取文本塞进详情。详情只展示被使用的证据。

# 6. 单封写信页面

页面目标：这是 Hermills 的核心价值页面。用户只输入客户邮箱和客户官网，软件自动背调、写信、评分和展示证据。

用户第一眼画面：标题“单封写信”，副标题“输入客户的网站和邮箱，Hermills 会自动背调官网并生成首封开发信。”主输入卡片位于左侧或中间，右侧可以是说明卡片或最近结果。输入态中，页面非常干净，只突出两个输入框和一个主按钮。

输入态布局：主卡片标题“单个客户”。说明“输入客户的网站和邮箱，AI 会自动背调官网并生成首封开发信。”两个输入框可以一行展示：客户邮箱、客户网站。窄屏下垂直排列。输入框下方有浅绿色自适应深度分析提示：“后台会优先深度抓取客户官网、产品页和联系页；失败时自动轻量兜底，不需要手动选择模式。”主按钮“分析客户官网并生成开发信”。

表单规则：客户邮箱必须合法。客户网站看起来必须是 URL。用户粘贴 company.com 时自动补 https://。按钮在邮箱和官网合法前禁用，并显示提示“请输入有效邮箱和客户官网后开始分析”。

生成中状态：点击主按钮后，输入卡片不消失，而是进入生成中布局。必须显示 AI 时间线：正在读取客户官网、正在提取业务线索、正在匹配公司资料、正在选择开发角度、正在生成开发信、正在进行质量检查、正在保存草稿。当前步骤蓝色 spinner，完成步骤绿色 check，等待步骤灰色圆点。超过 20 秒显示说明。深度抓取失败但轻量继续时显示黄色降级提示。

结果态布局：生成完成后显示结果布局。顶部提示“已生成开发信草稿。请先审核内容，确认后再发送。”结果区包括客户判断简报、推荐开发角度、邮件主题、可编辑邮件正文、质量评分、证据来源、操作按钮。

客户判断简报：显示客户类型、业务范围、可能采购角色、匹配产品、推荐开发角度和信心等级。每项都用短句，不要大段文字。

开发角度：显示 2 到 3 个角度卡。每张卡包括角度标题、为什么适合、不要声称什么、建议 CTA。选中的角度有蓝色边框。

邮件编辑：主题字段独立展示，正文是可编辑文本域或富文本区。正文旁边或下方显示质量评分。按钮包括保存草稿、重新生成、复制邮件、发送开发信。

质量分规则：90-100 显示优秀，80-89 显示可发送，60-79 显示建议修改，0-59 显示不能发送。低于 80 分时，主按钮必须是“重写到 80 分以上”，发送按钮降级并需要确认。

证据来源：每条证据显示页面标题、URL、证据句、作用。不要展示原始抓取大文本。

失败状态：官网读取失败时显示“客户网站暂时无法读取。Hermills 可以使用轻量信息继续生成，或你可以稍后重试。”按钮“继续轻量生成”和“重试读取”。完全失败时显示“Hermills 暂时没有完成生成。请先重试一次；如果还失败，复制详情给技术支持。”

禁止事项：不要让用户选择普通/深度模式。不要显示 Scrapling、Hermes Agent、token、API 调用链。不要把 AI 输出显示成一整段不可读文本。不要生成后只给邮件正文，不给证据和评分。

# 7. 批量写信页面

页面目标：让用户批量导入客户，逐条背调并生成开发信。批量不是黑盒等待，而是一条外联生产线。

用户第一眼画面：页面标题“批量写信”，副标题“上传客户列表，Hermills 会逐条背调并生成开发信。写好一封显示一封，不用等全部完成。”主区域上方是统计卡，中间左侧是导入卡，右侧是任务状态卡，下方是结果列表。

导入卡：支持文件上传和直接粘贴。拖拽区高度 180px，虚线边框，中央上传图标。文案“点击或拖拽上传 Excel / CSV 文件”。辅助“每一行至少包含邮箱；如果有官网，开发信会更精准。”粘贴框支持邮箱、官网、联系人。

解析预览：用户上传或粘贴后，不要直接开始。先显示解析预览，包括识别客户数、缺官网数量、重复邮箱数量、邮箱格式错误数量和前 5 行预览。用户确认后点击“选择文件并生成开发信”或“开始批量生成”。次按钮“仅导入客户”。

任务状态：显示当前任务名、总进度、已完成数量、失败数量、当前正在处理的客户。进度条显示“已完成 12 / 80”。下方显示当前步骤，例如“正在背调 buyer@company.com”。

队列行状态：排队中、正在背调、正在写信、待审核、可发送、失败。完成时行内浅绿闪 400ms。失败时浅红闪 400ms。失败不阻塞其他客户。

结果列表：每封邮件一个结果卡。卡片显示客户名、邮箱、官网、质量分、状态、完成时间。可展开查看邮件主题、正文、证据、评分。最新完成的结果默认出现在上方，但不要强制滚动抢用户位置，除非用户在顶部。

部分完成状态：批量任务中如果一部分成功一部分失败，页面不能显示整体失败。必须显示“已完成 48 / 80，失败 5 个，剩余 27 个继续处理中”。失败项可筛选查看。

失败状态：文件解析失败时显示“没有识别到有效客户。请确认文件中至少包含邮箱列。”按钮“重新选择文件”。单个客户失败时显示原因，例如“客户官网无法访问，已跳过背调。你可以补充官网后重试。”

禁止事项：不要只有一个大进度条。不要等全部完成才显示结果。不要一个失败导致整个任务停止。不要隐藏失败项。

# 8. 销售资产页面

页面目标：让用户维护会影响写信质量的销售材料。销售资产不是复杂资产库，而是写信材料库。

用户第一眼画面：页面标题“销售资产”，副标题“这些资料会帮助 Hermills 判断该用什么角度开发客户。资料越具体，邮件越不像模板。”页面主体由多个白色卡片组成，每张卡片是一个写信材料分区。

分区：产品和规格、证书和质量证明、样品政策、MOQ 和交期、案例和市场、常用 CTA。每个分区有标题、说明、输入区和保存状态。

交互：用户编辑后，底部或卡片右上显示“未保存”状态。点击“保存销售资产”后显示“已保存。之后生成的开发信会自动使用这些销售资产。”

禁止事项：不要做复杂数据库管理。不要展示 embedding、向量库、RAG、知识库索引等技术词。不要让用户填写大量结构化字段，除非字段对写信非常必要。

# 9. 邮箱配置页面

页面目标：让普通用户连接发件邮箱，不需要懂 SMTP。

用户第一眼画面：页面标题“邮箱”，副标题“连接你的发件邮箱，Hermills 才能发送开发信并检查回复。”顶部是邮箱状态卡。已连接显示绿色，未连接显示黄色，失败显示红色。下面是普通表单。高级设置折叠在底部。

普通表单字段：发件邮箱、邮箱授权码或 SMTP 密码、显示名称、外部测试收件箱。用户输入邮箱后，服务商识别卡自动出现。例如“已识别为 Gmail。请填写 Gmail 应用专用密码。”

主按钮：“保存并测试邮箱”。次按钮：“获取 SMTP 授权码”或“发送测试邮件”。

高级设置：折叠标题“高级设置（一般不用管）”。内部包含 SMTP 主机、SMTP 端口、安全协议、API 通道、API token、IMAP 设置。默认折叠。普通用户第一屏不看到这些字段。

成功状态：显示绿色提示“邮箱可用，可以发送开发信。”可以显示测试发送时间和测试收件箱。

失败状态：Gmail 授权失败时显示“邮箱授权失败。请确认你填写的是邮箱授权码，不是登录密码。”按钮“查看获取授权码方法”。连接超时时显示“邮箱服务器连接超时。请检查网络或稍后重试。”自定义 SMTP 错误显示人话摘要，技术详情折叠。

禁止事项：不要默认暴露 SMTP host、端口、SSL、API Base URL。不要显示 raw SMTP auth failed 作为主要错误。不要让用户配邮箱时像在配置服务器。

# 10. 签名 Logo 页面

页面目标：让用户维护邮件尾部签名和 Logo。保存一次，单封、批量和跟进开发信都会自动使用。

用户第一眼画面：页面标题“签名 Logo”，副标题“保存一次，之后单封、批量和跟进开发信都会自动带上。”主卡片标题“签名与 Logo”。左侧是文字签名和 Logo 上传，右侧是邮件尾部预览。

文字签名：textarea placeholder：

```text
Eckes
Anyway Flooring
anywayflooring.com
```

Logo 上传：支持 PNG、JPG、WebP，最大 2MB。上传后显示预览和删除按钮。没有 Logo 时显示上传占位。

预览区：白底、边框、圆角，像真实邮件尾部。预览显示文字签名、Logo 和官网。没有签名时显示“还没有文字签名。建议至少填写姓名、公司和官网。”

主按钮：“保存签名和 Logo”。成功提示：“签名已保存。之后生成的开发信会自动追加这份签名。”

禁止事项：不要默认展示 HTML 签名、Logo 宽度、alt 文本、自动追加开关等复杂设置。默认逻辑是只要有文字签名或 Logo，就自动追加到开发信。

# 11. 公司资料页面

页面目标：维护写信底层资料。它不是企业后台，而是 Hermills 判断开发角度和生成邮件时使用的公司信息。

用户第一眼画面：页面标题“公司资料”，副标题“Hermills 会用这些资料匹配客户需求，生成更具体的开发角度。”页面主体为分组卡片，底部有 sticky 保存按钮。

字段分组：公司基础，包括公司名和官网。产品，包括主营产品和规格范围。证明，包括证书、质检、案例。交易，包括 MOQ、交期、付款、物流。市场，包括目标国家和客户类型。风格，包括品牌语气和禁用说法。

交互：每组字段都有说明，告诉用户为什么这会影响开发信。保存按钮 sticky 在底部，文案“保存公司资料”。保存成功提示“已保存。之后生成的开发信会自动使用这份资料。”

禁止事项：不要把它做成复杂企业后台。不要展示数据库字段名。不要让用户填写过多不影响写信的字段。

# 12. 聊天控制页面

页面目标：让用户用微信、飞书、钉钉或 QQ 控制 Hermills，例如查看今日状态、写一封开发信、检查回复。

用户第一眼画面：页面标题“聊天控制”，副标题“绑定聊天平台后，你可以在手机上发送外联命令。”页面由平台选择卡、扫码绑定卡、命令测试卡、最近命令记录组成。

平台卡：微信、飞书、钉钉、QQ。每个平台显示图标、名称、状态：未连接、等待扫码、已连接、失败。选中平台有蓝色边框。

扫码绑定卡：未生成时显示二维码占位图标和按钮“生成扫码二维码”。已生成时显示二维码图片、绑定码、过期时间。已连接时显示绿色状态“连接成功，可以发送命令”。绑定过期时显示“二维码已过期，请重新生成”。

未配置云端地址状态：必须显示黄色提示“需要先配置云端绑定地址，才能生成手机可扫码二维码。”按钮“去系统设置”。此状态下不得生成坏二维码，不得出现 undefined/。

命令测试：textarea placeholder：“给 buyer@company.com https://company.com 写开发信”。快捷命令包括今日状态、待发送客户、写一封开发信、检查回复。执行中显示命令时间线。执行失败显示人话原因和复制详情。

最近命令记录：显示命令内容、来源平台、执行状态、时间、结果摘要。

禁止事项：不要在未配置公网绑定地址时生成二维码。不要显示 undefined、null、raw URL。不要把聊天控制做成开发者 webhook 配置页。

# 13. 系统设置页面

页面目标：放置低频、技术性、管理性设置，不影响每日外联主流程。

用户第一眼画面：页面标题“系统设置”，副标题“管理本地服务、AI 模型、同步和诊断。”页面使用分组卡片。技术信息可以在这里出现，但仍然要有清楚文案。

分组：Hermes 本地服务、AI 模型和 API Key、自动更新、数据同步、诊断日志、聊天控制云端绑定地址、隐私和本机数据。

本地服务卡：显示运行状态、版本、端口、启动/重启按钮、最近错误摘要。业务页面只显示人话摘要，完整日志只在这里。

AI 模型卡：显示当前模型、API Key 状态、测试连接按钮。API Key 输入必须隐藏，不能明文默认展示。

诊断日志卡：显示最近错误、复制诊断信息按钮、导出日志按钮。日志区域可以显示技术细节，但必须清楚标注“给技术支持使用”。

禁止事项：不要把系统设置混进每日工作页面。不要在系统设置以外的业务页面展示大量技术日志。不要让普通用户必须进入系统设置才能写第一封信。

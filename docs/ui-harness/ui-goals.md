# Hermills UI Harness Goals

## 总目标

Hermills 要看起来像一个清爽浅色 SaaS 外贸销售工作台。普通用户打开后，不需要懂 Hermes、Supabase、SMTP、token 或端口，也能完成注册、配置邮箱、添加客户、生成开发信、审核和发送。

每个页面都必须有一个主操作。页面如果不能让用户马上知道下一步，就算失败。

## 全局体验目标

- 视觉方向：清爽浅色 SaaS，专业、干净、稳定。
- 主色：蓝色用于主操作，绿色用于成功，红色用于危险，黄色用于提醒。
- 页面密度：业务页面可以信息丰富，但不能拥挤。
- 文案风格：像一个懂业务的助理，不像系统日志。
- 默认模式：普通用户模式。高级参数必须折叠。
- 结果呈现：AI 写完的内容要有证据、评分、修改入口。

## 页面目标

### 登录注册

目标：用户能顺利创建账号、收到验证码、登录，并在下次打开软件时保持登录。

要做的事情：
- 把注册、验证码、登录分成清楚状态。
- 成功后直接进入外联工作台。
- 失败时说清楚是邮箱、验证码、密码还是网络问题。

### 初始化

目标：用户一次性准备好写开发信需要的基础资料。

要做的事情：
- 公司资料、产品、市场、证书、贸易条款分步骤收集。
- 底部继续按钮必须永远可达。
- 上传资料只作为增强，不作为阻塞。

### 今日外联

目标：成为用户每天打开软件的首页。

要做的事情：
- 显示总客户、待生成、待发送、等待回复、已回复。
- 给出两个清楚入口：写单封开发信、批量写开发信。
- 显示邮箱和公司资料是否准备好。

### 客户管理

目标：用户能维护客户，并查看每个客户的背调和邮件。

要做的事情：
- 搜索框必须好用。
- 状态筛选必须明显。
- 客户详情要显示：客户信息、背调摘要、证据来源、邮件主题、正文、质量分、下一步。

### 单封写信

目标：用户输入一个客户邮箱和官网，点击一个按钮，得到一封可审核的英文开发信。

要做的事情：
- 保留一个主按钮：分析客户官网并生成开发信。
- 后台自动自适应深度分析，不让用户选择普通/深度。
- 生成结果必须包含问候、正文、CTA、尾款签名。
- 生成过程可以折叠查看，不打扰普通用户。

### 批量写信

目标：用户导入客户表格后，每个客户单独背调和写信，逐条返回结果。

要做的事情：
- 支持 Excel、CSV、复制粘贴。
- 一个邮箱代表一个客户。
- 批量任务不等全部完成；写好一封显示一封。
- 失败客户显示失败原因，其他客户继续跑。

### 销售资产

目标：作为写信底层资料库，不作为复杂后台。

要做的事情：
- 保留买家会关心的资料：产品、证书、样品政策、MOQ、交期、案例、付款和物流。
- 告诉用户这些资料会影响开发信质量。
- 不要求用户填写复杂标签。

### 邮箱配置

目标：普通用户只填自己的邮箱和授权码，系统自动判断通道并测试。

要做的事情：
- 默认显示：邮箱、授权码、显示名称、测试收件箱。
- Gmail、Outlook、腾讯、阿里、Zoho 自动识别。
- SMTP 主机、端口、API 参数放进高级设置。

### 签名 Logo

目标：用户只保存文字签名和 Logo，以后所有开发信自动带上。

要做的事情：
- 只保留文字签名、上传 Logo、预览、保存。
- 不显示 HTML 签名、Logo 宽度、替代文字等高级字段。
- 预览要像真实邮件签名。

### 公司资料

目标：成为匹配开发信角度的长期资料库。

要做的事情：
- 突出“这些资料会被用来写信”。
- 重点字段：公司名、官网、主营产品、优势、证书、目标市场、样品政策、贸易条款。
- 保存后在侧边栏显示公司资料已准备。

### 聊天控制

目标：用户可以通过微信、飞书、钉钉、QQ 控制 Hermills。

要做的事情：
- 每个平台有独立连接状态。
- 点击生成二维码后，展示真实可访问链接。
- 扫码后软件显示连接成功，并提供测试命令，比如“今日状态”。
- 如果未配置公网地址，明确提示“需要先配置云端绑定地址”，不能生成 `undefined/`。

## 不做的事情

- 不把普通用户变成系统管理员。
- 不让用户在业务流程里选择复杂技术模式。
- 不在外联链路里展示无关 Hermes 内部细节。
- 不通过加更多卡片来掩盖流程不清。

# Hermills UI Harness Project Map

## 项目一句话说明

Hermills 是一个 Windows 桌面端外贸开发信工作台，核心流程是：登录 -> 公司资料 -> 邮箱 -> 客户 -> 背调 -> 写信 -> 审核 -> 发送 -> 跟进 -> 学习。

这份地图只负责告诉实现 Agent 和验收 Agent：项目在哪里、页面有哪些、哪些规则不能破坏。

## 核心用户路径

1. 新用户打开软件，完成登录注册和初始化。
2. 用户填写公司资料、产品、市场、证书、签名和 Logo。
3. 用户配置发件邮箱，系统自动测试是否能发信。
4. 用户添加单个客户，或批量导入客户。
5. Hermills 背调客户官网，匹配公司资料，生成开发信。
6. 用户查看背调、证据、邮件主题、正文、质量分。
7. 用户修改、保存、发送邮件。
8. Hermills 检查发给客户邮箱的回复，提醒跟进。
9. 软件记录脱敏学习数据，用于改进写信系统。

## 页面地图

| 页面 | 当前职责 | 主要风险 |
| --- | --- | --- |
| 登录注册 | 账号创建、验证码、登录、记住状态 | 验证流程不清楚，错误提示像技术日志 |
| 初始化 | 语言、身份、公司资料、供应商、工作区、功能选择 | 页面过长，按钮不可达，步骤太像工程设置 |
| 今日外联 | 总览今天的客户、待写、待发、回复和跟进 | 信息太少或像空页面，用户不知道下一步 |
| 客户管理 | 客户列表、筛选、草稿查看、详情审核 | 左右面板拥挤，邮件质量和证据不够显眼 |
| 单封写信 | 输入一个客户官网和邮箱，生成开发信 | 错误条遮挡，生成过程慢，结果区域不清楚 |
| 批量写信 | 导入文件，批量背调和生成邮件 | 不能逐条呈现会让用户以为卡住 |
| 销售资产 | 公司卖点、买家画像、CTA 资产 | 容易变成复杂后台，普通用户不知道为什么填 |
| 邮箱配置 | 保存发件邮箱、授权码、测试发信 | 复杂参数外露，用户不知道填什么 |
| 签名 Logo | 保存文字签名和 Logo | 字段过多会让用户误以为要懂 HTML |
| 公司资料 | 维护写信底层资料库 | 太像后台表单，和写信关系不明显 |
| 聊天控制 | 绑定微信、飞书、钉钉、QQ，聊天操作 Hermills | 二维码链接错误，`undefined/` 会直接破坏信任 |
| 系统设置 | Hermes、API Key、诊断、更新 | 技术设置必须和业务工作台分层 |

## UI 开发约束

- 外联链路统一使用清爽浅色 SaaS 风格。
- 每个页面必须只有一个最明显的主操作。
- 业务页面优先展示用户下一步，而不是展示技术能力。
- 设置类页面默认只露出普通用户必填项，高级项折叠。
- 错误提示必须告诉用户下一步怎么做。
- 长页面必须允许内容区滚动，不能把按钮卡出屏幕。
- 任意页面不能出现页面级横向滚动。
- 任意二维码、外部绑定链接不能出现 `undefined/`。

## 禁止事项

- 不允许新增另一套孤立颜色系统。
- 不允许灰色按钮文字看不清。
- 不允许图标和文字重叠。
- 不允许把 SMTP、token、端口等高级概念直接堆给普通用户。
- 不允许让实现 Agent 自己宣布视觉通过。
- 不允许只写“测试通过”，必须给出命令、截图或日志证据。

# Hermills UI Harness Page Inventory

## 使用方式

实现 Agent 改 UI 前，先看本清单。每个页面都必须明确：用户任务、主要操作、UI 风险、验收证据。

| 页面 | 用户任务 | 主要操作 | UI 风险 | 验收证据 |
| --- | --- | --- | --- | --- |

| 今日外联 | 查看今天要处理的客户和任务 | 去写单封开发信、去批量写信、检查邮箱 | 空白感强；卡片太散；下一步不明确 | 首页首屏截图；统计卡片和主按钮截图 |

## 用户流程清单

| 流程 | 必经页面 | 验收重点 |
| --- | --- | --- |
| 新用户第一次使用 | 登录注册 -> 初始化 -> 公司资料 -> 邮箱配置 -> 今日外联 | 不需要理解技术概念；所有下一步按钮可见 |
| 老用户每天使用 | 今日外联 -> 客户管理 -> 单封写信/批量写信 -> 发送/跟进 | 首页能告诉用户今天做什么 |
| 单个客户写信 | 单封写信 -> 客户管理详情 -> 邮件审核 -> 发送 | 一个按钮完成背调和写信；结果必须能审核 |
| 批量客户写信 | 批量写信 -> 客户管理 -> 逐条审核 -> 批量发送 | 写好一封显示一封；失败不阻塞其他客户 |
| 邮箱连接 | 邮箱配置 -> 保存并测试 -> 外部收件箱测试 | 普通用户只填邮箱和授权码 |
| 手机聊天控制 | 聊天控制 -> 生成二维码 -> 扫码 -> 发命令 | 扫码链接真实可用；连接成功可见 |

## 统一 UI 风险

- 页面主按钮不明显。
- 禁用按钮灰白导致看不清。
- 长文本和图标重叠。
- 提示条覆盖输入框。
- 内容区滚动和页面滚动冲突。
- 空状态没有告诉用户下一步。
- 业务页面出现过多技术词。

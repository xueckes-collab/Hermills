# Hermills Motion Feedback Harness

## 一句话方向

Hermills 的每一次点击都必须让用户马上知道软件听见了，每一个超过 600ms 的动作都必须让用户知道正在做什么，每一个完成、失败、可重试状态都必须给用户一个清楚的收尾。

这套动效不是装饰，而是工作台的信任系统。用户点了“分析客户官网并生成开发信”“批量导入并生成”“保存并测试邮箱”“同步学习数据”之后，不能只能傻等。

## 实现地图

### 1. 即时点击反馈层

覆盖范围：
- 原生 `button`
- `apps/renderer/src/components/ui/button.tsx` 的通用 `Button`
- `apps/renderer/src/components/outreach-ui.tsx` 的 `OutreachButton`
- 侧边栏导航按钮、图标按钮、筛选按钮、文件上传按钮、批量任务按钮、邮箱测试按钮、同步按钮

设计要求：
- 鼠标悬停时轻微抬起或增强边框。
- 鼠标按下时 80-120ms 内下压，不改变布局尺寸。
- 键盘 focus 必须有清晰可见的焦点环。
- 禁用状态不能灰到看不清，必须显示“不可点但可读”。
- 所有按钮统一使用 `data-feedback="button"` 作为可测试契约。

### 2. 加载反馈层

覆盖范围：
- 单封写信：客户背调、生成邮件、重写邮件、保存草稿。
- 批量写信：文件解析、客户入队、逐条背调、逐条写信、逐条保存。
- 邮箱：保存配置、测试发信、检查回复。
- 公司资料：保存资料、上传资料、同步学习数据。
- 聊天控制：生成二维码、测试命令、解除绑定。
- 系统设置：诊断、安装/更新 Hermes、检查更新。

设计要求：
- 按钮进入加载时必须设置 `aria-busy="true"` 或 `data-loading="true"`。
- 加载按钮必须出现小 spinner 或轻微流光，不能只把文字换成“处理中...”。
- 加载中的按钮保持原有宽度，避免文字变化导致布局跳动。
- 一个操作如果超过 600ms，页面上必须出现阶段说明。
- 一个操作如果超过 2s，必须显示进度条或步骤列表。

### 3. 长任务进度层

覆盖范围：
- 深度分析客户官网并生成开发信。
- 批量客户导入和批量生成开发信。
- 邮箱测试和回复检测。
- 云端学习数据后台同步。
- 安装/更新/诊断类系统任务。

阶段模型：
1. 准备任务：读取输入、检查必填项、锁定客户。
2. 执行任务：背调、匹配、写信、测试、同步。
3. 保存结果：写入客户记录、草稿、学习事件。
4. 收尾反馈：完成、失败、可重试、部分成功。

设计要求：
- 进度条用 indeterminate 动效，不假装知道百分比。
- 批量任务必须逐条显示结果，写好一封显示一封。
- 失败不能盖住成功结果；失败条目显示原因和重试入口。
- 页面顶部允许短暂 toast，但长任务必须在页面内容区有稳定位置。

### 4. 结果反馈层

覆盖范围：
- 成功保存、成功生成、成功发送、连接成功、同步成功。
- 本地服务失败、模型失败、网站抓取失败、邮箱测试失败、同步失败。
- 部分成功：批量任务中部分客户失败。

设计要求：
- 成功反馈用绿色小提示，3-5 秒后可自动消失。
- 警告反馈用黄色，必须告诉用户下一步。
- 错误反馈用红色，必须有复制详情或重试入口。
- 不能只显示“本地服务失败”；必须翻译成用户能懂的业务语言。

### 5. 可访问性和性能层

覆盖范围：
- 所有动效、spinner、progress、skeleton、toast。

设计要求：
- 必须支持 `prefers-reduced-motion: reduce`，用户要求减少动效时只保留必要状态变化。
- 动效只使用 transform、opacity、background-position，避免触发布局抖动。
- spinner 和流光不能影响文本可读性。
- 动效时间统一：点击 80-120ms，悬停 140-180ms，加载循环 800-1200ms，toast 入场 180-220ms。

## 实现目标

### 目标 1：所有按钮有即时反馈

用户点任意按钮后，100ms 内能看到按压反馈。即使后端还没有响应，用户也知道软件接收到点击。

验收重点：
- 原生按钮、通用 Button、OutreachButton 都有 `data-feedback="button"` 或统一 CSS 覆盖。
- hover、active、focus-visible、disabled 状态都存在。
- 按压反馈不改变按钮尺寸。

### 目标 2：所有异步按钮有加载状态

用户触发异步任务时，按钮必须进入不可重复点击状态，并显示 spinner、流光或清楚的加载文本。

验收重点：
- 有 `aria-busy="true"` 或 `data-loading="true"`。
- loading 状态不让按钮文字看不清。
- loading 状态不让布局跳动。

### 目标 3：长任务有页面级进度

写信、批量、邮箱测试、同步等长任务必须在页面上显示阶段。用户不需要猜软件卡没卡。

验收重点：
- 单封写信显示“正在读取客户官网 / 正在生成开发信 / 正在保存草稿”。
- 批量写信显示队列、进行中、成功、失败。
- 同步学习数据显示“后台自动同步中 / 已更新 / 稍后重试”。

### 目标 4：失败状态可理解、可恢复

失败不是终点。用户必须知道失败在哪里、能不能重试、要不要复制详情。

验收重点：
- 错误条不遮挡主按钮和输入框。
- 有重试或复制详情入口。
- 技术错误被翻译成用户下一步。

### 目标 5：动效不牺牲稳定和可访问性

Hermills 是工作软件，动效必须克制、清楚、稳定，不做花哨干扰。

验收重点：
- `prefers-reduced-motion` 下动画被压缩或关闭。
- 动效不造成横向滚动、重叠、文字抖动。
- 低性能机器上也不明显掉帧。

## 验收标准

### 静态合同验收

必须有测试确认：
- CSS 中存在 motion token：`--motion-duration-fast`、`--motion-duration-standard`、`--motion-ease-standard`。
- CSS 覆盖 `button`、`[data-slot="button"]`、`.outreach-button` 的 hover、active、focus-visible、disabled。
- CSS 覆盖 `[aria-busy="true"]` 和 `[data-loading="true"]`。
- CSS 存在 spinner、indeterminate progress、busy sheen 的 keyframes。
- CSS 存在 `@media (prefers-reduced-motion: reduce)`。
- `OutreachButton` 渲染 loading 时输出 `aria-busy="true"`、`data-loading="true"`、`data-feedback="button"` 和 spinner。
- 通用 `Button` 输出 `data-feedback="button"`，让全局动效能覆盖旧页面按钮。

### 页面体验验收

必须在 1366x768、1440x900、1280x720 检查：
- 单封写信：按钮点击后立刻反馈，生成中有阶段说明。
- 批量写信：上传后有文件解析反馈，队列逐条变化。
- 客户管理：删除、筛选、查看详情有点击反馈。
- 邮箱配置：保存并测试有 loading，失败提示可恢复。
- 公司资料：保存按钮和同步状态反馈清楚。
- 聊天控制：生成二维码按钮有 loading，失败时不出现 `undefined/`。
- 系统设置：诊断、更新、安装 Hermes 有明确进度。

### 用户感受验收

从用户角度必须满足：
- 点了按钮，马上知道点到了。
- 等待超过 2 秒，知道软件正在做哪一步。
- 失败时知道下一步怎么做。
- 不会因为按钮变灰、文字变浅、布局跳动而怀疑软件坏了。

### 不合格示例

- 按钮只换文字，没有 spinner 或 busy 属性。
- 按钮 loading 时文字变成白底白字或灰底浅灰字。
- 批量任务上传后 5 秒没有任何变化。
- 生成开发信时用户只能看到按钮灰掉。
- 错误提示盖住输入框。
- 用户开启 reduced motion 后仍然有大量循环动画。
